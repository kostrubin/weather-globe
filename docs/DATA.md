# Data contracts and semantics

Verified with real completed runs on 2026-10-20/21 UTC. This is sample evidence, not a provider SLA.

| Map           | Model / raw variable                                            | Native grid     | Normalized unit / interpretation                                                         |
| ------------- | --------------------------------------------------------------- | --------------- | ---------------------------------------------------------------------------------------- |
| Temperature   | ecmwf_ifs025 / temperature_2m                                   | 1440×721, 0.25° | °C, 2m air                                                                               |
| Precipitation | ecmwf_ifs025 / precipitation                                    | same            | mm over preceding valid-time interval → mm/h interval-average; initial frame unavailable |
| Wind          | ecmwf_ifs025 / wind_u_component_10m, wind_v_component_10m       | same            | m/s; magnitude from u/v, FROM bearing shown separately                                   |
| Cloud         | ecmwf_ifs025 / cloud_cover                                      | same            | total percent; no satellite or volume claim                                              |

Endpoints: `https://openmeteo.s3.amazonaws.com/data_spatial/{model}/latest.json`. Validate `completed:true`, ordered valid_times and variables. Immutable frame URL comes from the documented run layout, e.g. `/ecmwf_ifs025/2026/10/20/1200Z/2026-10-21T0000.om`. Root run/valid epoch seconds and CRS must match the manifest; native shapes and child unit metadata are checked. This release supports these verified grids, rejecting incompatible schema drift.

IFS/global rows run south→north, longitude −180→east with a periodic seam. Europe rows are north→south and reversed once. Its centre bounds are west−24.95, south30.05, east44.95, north71.95; mask outside this extent. Source and display shapes remain separate. No-data/NaN never becomes zero. Negative precipitation artifacts observed at −0.1mm are marked invalid, not clamped to zero. No cumulative differencing is used.

OM 0.0.20 already applies storage scale/offset. Temperature, pressure and concentration are not converted a second time. Selected variable(s) are decoded in a threadless Worker, then subsampled to a display grid. Reading the native variable does **not** reduce its transfer; typical measured per-frame transfer was0.125–1.44MiB, not the43.6MB multi-variable IFS file. Numeric texture and CPU samples use the same masked bilinear interpolation and fixed physical palette. Four actual output pixels matched expected RGB exactly in browser verification.

Timeline uses actual metadata steps (IFS3h in the verified horizon; CAMS hourly samples verified), restricted to now−3h through now+72h and source availability. Precipitation skips the first run step. A missing variable at a later provider frame produces unavailable state rather than an invented field. Requested tuple and committed map/legend tuple stay separate. Nearest-time adjustment is visible. UTC instants are distinct from run/retrieval times. Local forecasts use provider IANA timezones. Expired URL times are adjusted visibly; old runs are not promised retained.

Range backend: conditional ETag/Last-Modified, exact206 Content-Range and bounded streaming before allocation; reject ignored ranges/version mismatch. 64KiB blocks,160-block LRU per Worker, up to3 concurrent prefetches per variable. Frame LRU6 entries keyed by layer/species/run/metadata version/time/quality. Scalar and optional overlay have separate workers, ID-scoped cancellation, and only latest requests commit. Wind overlay requires exact matching valid time; both model runs remain identified. No whole-horizon startup downloads or hidden-tab polling. Completed metadata revalidates every 10 minutes while visible and on Now; a new run commits atomically. Manual retry after an honest error; hosted point retries exclude 429. No public proxy or credential required.

Particles use real u/v, spherical tangent integration and a bounded batched CPU draw (8192 high /2048 low). Motion is accelerated 3000×; short transport-direction segments use the same vectors. Clamp frame delta, handle poles/seams and pause hidden/reduced-motion views. Reduced motion keeps scalar speed and numerical FROM direction.

Point APIs: `/v1/forecast` (7days, numeric UTC epochs, timezone auto, m/s), `/v1/air-quality` (PM2.5, **European AQI**, all-sky UV and in-Europe pollen), and `/v1/search` (debounced 300 ms, language/country/admin labels). Only committed selected coordinates, rounded to3 decimals, are requested. Cache 20 min, abort stale requests, no hover/drag requests. No inferred reverse geocoding. Local and map values may differ because sources/resolutions differ.

Hosted free service remains personal/noncommercial and quota limited. Published research baseline:600/min,5000/h,10000/day and300000/month; current pricing/terms pages returned403 in this environment, so these are **not revalidated current allowances**. The app has no quota-evasion mechanism, billing, account, analytics or server. Data CC BY4.0 is separate from service terms and GPL code. Contains modified Copernicus CAMS/ECMWF data; visible attribution and detailed Sources are provided. Natural Earth coastlines are public domain. No WMS fallback was needed because all required numeric OM modes passed real browser tests.

Daily civil dates need a separate normalization: the verified point API uses fixed24h daily anchors and the response's `utc_offset_seconds`. Add that offset and read the calendar date in UTC; do not interpret these anchors as IANA midnights across DST. Hourly instants receive **no** added offset. A real Berlin DST regression (2026-10-25) is covered by a deterministic test, yielding seven unique dates21–27 Oct instead of a duplicate25Oct.
